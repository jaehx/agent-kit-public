# AI로 감각 있는 디자인 만들기: 참고 사이트와 쓰는 법

AI에게 디자인을 맡기면 보라색 그라데이션, 둥근 카드 그리드, 이모지 아이콘 같은 결과가 자주 나옵니다.
모델이 학습 데이터에서 가장 흔한 형태, 즉 평균값을 출력하기 때문입니다.
지시가 막연할수록 결과는 평균으로 돌아갑니다.

해결 방법은 취향은 사람이 정하고 AI에게는 실행만 맡기는 것입니다.
이 문서는 취향을 정할 때 참고할 사이트와, 그 레퍼런스를 Claude에게 전달하는 방법을 정리합니다.

## 1. 참고 사이트

목적에 따라 볼 곳이 다릅니다. 서비스 화면(제품 UI)을 참고하려면 Mobbin이나 Refero부터 보세요.

### 실제 서비스의 화면과 흐름 (제품 UI·UX)

| 사이트 | 특징 |
|---|---|
| [Mobbin](https://mobbin.com) | 실제 출시된 앱·웹 화면 모음. "온보딩", "결제", "설정"처럼 흐름 단위로 검색. 일부 기능 유료 |
| [Refero](https://refero.design) | Mobbin과 비슷하고 웹 SaaS 화면이 강함. 컴포넌트·패턴 단위 검색이 편함 |
| [Page Flows](https://pageflows.com) | 화면이 넘어가는 과정을 영상으로 보여 줌. 가입·결제처럼 이어지는 흐름을 볼 때 좋음 |

### 랜딩 페이지·마케팅 사이트

| 사이트 | 특징 |
|---|---|
| [Godly](https://godly.website) | 감각적인 웹사이트 선별 모음. 움직임까지 미리 볼 수 있음 |
| [Land-book](https://land-book.com), [Lapa Ninja](https://www.lapa.ninja) | 랜딩 페이지 모음. 업종별 탐색 |
| [SaaS Landing Page](https://saaslandingpage.com), [Saaspo](https://saaspo.com) | SaaS 랜딩 페이지만 모은 곳 |
| [Minimal Gallery](https://minimal.gallery), [Siteinspire](https://www.siteinspire.com) | 절제된 스타일 위주. "AI 느낌"을 덜어 내는 연습에 좋음 |

### 원리를 배우는 곳

- [Laws of UX](https://lawsofux.com): 피츠의 법칙, 힉의 법칙 같은 UX 원칙을 한 장씩 정리.
- [Nielsen Norman Group](https://www.nngroup.com): UX 연구 기반의 글. "왜 이렇게 해야 하는가"의 근거를 찾을 때.
- 공개된 디자인 시스템: 토스(TDS), Apple HIG, Material, Atlassian, Vercel(Geist).
  간격, 글자 크기, 색 체계를 그대로 참고할 수 있습니다.

### 피할 곳

Dribbble과 Behance는 실제 서비스가 아니라 콘셉트 시안이 대부분입니다.
보기에는 멋지지만 실제 데이터, 에러 상태, 긴 텍스트를 고려하지 않은 경우가 많아 제품 UI 참고용으로는 맞지 않습니다.

> 사이트 주소와 유료·무료 여부는 바뀔 수 있습니다.

## 2. Claude에게 레퍼런스를 전달하는 법

### 형용사 대신 스크린샷을 준다

"모던하고 깔끔하게"는 평균으로 돌아가라는 말과 같습니다.
마음에 드는 화면 2~3개의 스크린샷을 직접 주고, 먼저 분석하게 합니다.

```
첨부한 화면 3개의 공통점을 분석해서 디자인 토큰으로 정리해 줘.
글자 크기 단계, 간격 단위, 색(배경·표면·본문·보조·강조), 모서리 반경, 그림자 사용 여부.
구현은 아직 하지 말고 토큰 표만 보여 줘.
```

토큰을 확인하고 고친 다음에 구현을 시킵니다. 레퍼런스를 말로 설명하는 것보다 결과가 훨씬 안정적입니다.

### 디자인 토큰을 먼저 고정한다

글자 크기 단계, 간격 단위, 색 4~5개, 모서리 반경을 CSS 변수나 Tailwind 설정으로 먼저 정합니다.
선택지가 줄어들수록 AI가 평균으로 돌아갈 여지도 줄어듭니다.
토큰 밖의 값(임의의 `#hex`, `13px` 같은 값)을 쓰지 말라고 함께 지시합니다.

### 금지 목록을 쓴다

하지 말아야 할 것을 적는 편이 하라는 지시보다 효과가 큰 경우가 많습니다.
프로젝트 `CLAUDE.md`에 넣어 두면 매번 말하지 않아도 됩니다.

```markdown
## 디자인 금지 사항
- 그라데이션 배경, 그라데이션 텍스트 금지
- 이모지를 아이콘 대신 쓰지 않는다
- 모든 콘텐츠를 카드로 감싸지 않는다. 구분은 간격과 구분선으로 먼저 해결
- 강조색은 화면당 한 곳(주요 행동 버튼)에만
- 토큰에 없는 색·크기 값을 새로 만들지 않는다
```

### 결과를 눈으로 보고 고치게 한다

코드만 보고 고친 디자인은 실제 화면과 어긋나기 쉽습니다.
Playwright나 Chrome DevTools MCP로 스크린샷을 찍어 Claude가 결과물을 직접 보고 고치게 합니다.

```
수정할 때마다 데스크톱(1440px)과 모바일(390px) 스크린샷을 찍어서
첨부한 레퍼런스와 비교하고, 다른 점을 목록으로 적은 뒤 고쳐 줘.
```

### 실제 콘텐츠를 넣는다

lorem ipsum으로 만든 화면은 실제 데이터가 들어가면 무너집니다.
긴 이름, 빈 목록, 에러 메시지, 숫자가 큰 경우를 처음부터 넣고 확인합니다.

## 3. 한계

AI는 취향을 실행할 수는 있어도 만들어 내지는 못합니다.
가장 효과가 큰 방법은 디자이너에게 디자인 시스템과 핵심 화면 몇 개만 받고,
나머지 화면은 AI가 그 체계에 맞춰 일관되게 만들게 하는 것입니다.
