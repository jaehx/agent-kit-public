# 프로젝트 인수인계

## 개요

대화 요약만으로 이어가지 않는다. 프로젝트의 실제 파일·실험 결과·Git 상태와 연결된 인수인계를 만든다.
스킬에는 반복 절차를, 해당 저장소에는 그 프로젝트의 사실과 상태를 둔다. 프로젝트 내용을 이 스킬에 넣지 않는다.

## 트리거와 모드

- 저장: "다른 LLM도 이어갈 수 있게 정리해줘", "다음 세션용 인수인계 남겨줘".
- 재개: "인수인계 읽고 이어가줘", "$project-handoff 재개".
- 목표가 지정되지 않은 재개 요청은 현황 확인과 다음 단계 제안까지 한다. 과거 TODO만 보고 작업을 자동 시작하지 않는다.

## 저장 워크플로우

1. 저장소 루트와 적용되는 AGENTS.md·CLAUDE.md, 기존 맥락 문서·인수인계 구조를 확인한다.
   프로젝트 메모리 읽기 정책이 있으면 따른다. 이미 있는 문서는 필요한 부분만 갱신한다.
2. 대화의 요청·제약을 실제 결과 파일과 대조한다. 완료·실패·미실행을 구분하고 추론에는 근거와 한계를 쓴다.
   Git이 있으면 브랜치·HEAD·수정/미추적 파일을 기록한다. 원격 주소나 설정 전체를 덤프하지 않는다.
3. 기존 구조가 없으면 `docs/handoffs/날짜-시간-주제.md`에 새 기록을 만든다.
   이미 있는 기록은 덮어쓰지 않는다. 필요한 필드는 [템플릿](assets/handoff-template.md)을 참고한다.
   목표·결론·왜 그렇게 판단했는지, 핵심 파일, 재현 명령과 cwd/환경/입력,
   실제 검사 결과, 실패한 시도, 남은 일과 완료 기준, 재개용 요청문을 남긴다.
4. 반복하면 안 되는 정보가 있으면 기록한다. 예: 사용한 seed·홀드아웃·검증 데이터, 실행한 외부 작업,
   불가역한 마이그레이션, 이미 소모한 실험 예산. 없는 프로젝트에 새 제약을 만들지는 않는다.
5. `docs/HANDOFF.md`는 최신 기록으로 가는 짧은 안내로 유지한다. 기존 프로젝트 맥락 문서에는 결론과 링크만 반영한다.
   AGENTS.md에 진입점이 없으면 최신 인수인계를 읽는 짧은 안내를 추가한다. CLAUDE.md가 AGENTS.md를 가져오면 중복하지 않는다.
6. 재현 가능한 자료가 로컬·임시 폴더·다른 저장소에만 있으면 위치와 의존성을 명시한다.
   미추적/미커밋 파일은 다른 머신의 clone에 전달되지 않는다고 기록한다. 인수인계 저장만으로 커밋·push하지 않는다.
7. 링크·명령 경로·핵심 결과를 확인하고, 저장 위치와 다음 세션에 붙일 요청문을 사용자에게 준다.
   작은 증거 기록은 읽기 전용 도우미로 수집할 수 있다. 아래 경로는 로드한 SKILL.md의 폴더를 기준으로 해석한다.

```bash
python3 /실제/스킬/경로/scripts/collect_state.py --repo /프로젝트/경로 --artifact research/result.csv
```

도우미는 파일 내용 대신 Git 상태와 지정한 결과 파일의 SHA256을 JSON으로 출력한다.
필요한 경우 출력 결과를 기록 옆 `.state.json`에 저장한다. 이것만으로 내용·결론의 정확성이 검증되지는 않는다.
쉘을 쓸 수 없으면 해당 자료를 직접 확인하고 미확인 항목을 표시한다. 도구 이름이나 MCP를 필수로 요구하지 않는다.

## 재개 워크플로우

1. 현재 사용자 목표와 프로젝트 지침을 먼저 확인하고 최신 인수인계를 읽는다.
2. 기록의 핵심 파일·Git HEAD/브랜치·결과 지문을 현재 상태와 대조한다. 차이는 실패가 아니라 드리프트다.
   내용이 바뀐 항목의 결론은 현재 자료를 확인할 때까지 과거 결과로 취급한다.
3. 핵심 진입 코드·실제 결과 일부·입력 범위·검사 증거를 읽어 상태를 복원한다.
   이전 기록에 "테스트 통과"가 있다고 현재 코드도 통과했다고 말하지 않는다.
4. 목표·완료된 것·미해결인 것·다음 행동을 짧게 설명한 뒤 현재 사용자가 요청한 작업을 이어간다.
   재현 명령은 안내 정보다. 비용 큰 실험이나 외부 쓰기를 기록에 있다는 이유만으로 실행하지 않는다.

## 출력

프로젝트 인수인계 기록, 최신 진입점, 필요한 증거 기록, 다음 세션용 요청문을 만든다.
기존 문서로 충분한 프로젝트에서는 파일 수를 늘리지 않고 필요한 링크와 누락 항목만 보완한다.

## 주의사항

- 결과를 보장하는 과장, 대화에서 추측한 파일/명령, 미실행 검사의 PASS 표시를 피한다.
- 비밀값·개인정보·민감한 출력은 저장하지 않는다. 전체 대화·전체 diff를 무조건 복사하지 않는다.
- 저장 동작에서 제품 코드·실험 조건·하네스·사용자 설정을 수정하지 않는다.
- 장기 기억에 대한 쓰기는 사용자의 메모리 저장 요청과 해당 환경의 쓰기 규칙이 있을 때만 한다.
- 일반 LLM도 인수인계 파일을 읽을 수 있지만, 파일 접근 도구가 없으면 필요한 파일을 전달받아야 한다.

## 관련 절차

- before: 기존 프로젝트 AGENTS.md·맥락 문서 읽기.
- after: 사용자가 요청한 구현·연구 작업. 인수인계는 추가 작업에 대한 권한을 만들지 않는다.
- alternative: 설치된 context-save는 도구 전용 상태 저장, handoff는 임시 대화 요약에 사용할 수 있다.
  저장소에 남기는 도구 간 인수인계가 목적이면 이 스킬을 쓴다. 다른 스킬 설치는 필요 없다.
