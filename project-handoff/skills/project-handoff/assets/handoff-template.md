# 프로젝트 인수인계 — 제목

작성 시각·시간대와 마지막으로 확인한 저장소 루트·브랜치·HEAD를 기록한다.
아래는 문장 그대로 출력할 빈 양식이 아니라 필요한 항목을 선택하는 작성 기준이다.

## 목적과 상태

사용자 목표, 작업 범위, 현재 작업의 완료/진행/차단 여부.
여전히 필요한 작업과 제안만 한 작업을 구분한다.

## 확인된 결론과 판단 근거

핵심 결론과 실제 파일·수치·검사 근거의 링크. 채택/기각 이유.
실패한 접근과 되풀이하지 않을 이유. 추론·가정·불확실성.

## 최소 읽기 순서

프로젝트 지침 → 최신 맥락 → 관련 결과 → 재개할 코드.
핵심 파일의 역할과 각 경로가 저장소 기준인지 외부 의존성인지 표시한다.
대량 문서나 전체 기록 대신 다음 행동에 필요한 파일만 지정한다.

## 재현과 검증

명령별 작업 디렉터리, 런타임/의존성, 데이터 기간·지문·설정, 실제 관측 결과.
검사 날짜, 미실행 검사와 이유. 큰 실험을 재실행해야 하는 조건.
사용한 seed/검증 세트/외부 실행과 같은 재사용 주의사항은 해당 작업에 있을 때만 적는다.

## 변경 상태와 전달 범위

현재 Git 상태, 미추적 파일, 미커밋 변경, 외부 파일/다른 저장소/서비스 의존성.
다른 머신에 가져갈 때 전달해야 할 파일. 코드 내용 대신 증거와 지문을 링크한다.

## 남은 일

우선순위별 구체적 행동, 시작 파일, 검증 방법과 완료 기준.
현재 사용자에게 승인된 작업과 이후 판단/제안만 한 작업을 구분한다.

## 다음 세션용 요청문

저장소, 읽을 진입점, 이어갈 목적, 필요한 제약을 포함한 짧은 복사 가능한 요청문.
다음 목적이 미정이면 먼저 상태를 확인하도록 쓰고 새 작업을 임의 지정하지 않는다.
